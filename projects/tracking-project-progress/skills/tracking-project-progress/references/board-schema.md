# Project board schema

`state.json` is the source of truth. `board.md` is regenerated from it and `events.jsonl` is append-only audit history. Agents must use `scripts/project_board.py` for mutations rather than editing JSON directly.

## Files

| Path | Purpose |
| --- | --- |
| `.project-board/state.json` | Machine-readable current state |
| `.project-board/board.md` | Human-readable rendered board |
| `.project-board/events.jsonl` | Revision event history |
| `.project-board/.lock/` | Short-lived atomic mutation lock |

## State fields

| Field | Type | Rule |
| --- | --- | --- |
| `schema_version` | string | Exactly `1.0` |
| `revision` | positive integer | Increments once per mutation |
| `created_at`, `updated_at` | UTC ISO-8601 strings | Generated by the CLI |
| `project` | object | Non-empty `name`, canonical `root`, and `objective` |
| `status` | enum | `active`, `blocked`, or `complete` |
| `phase` | string | Short project phase label |
| `current_focus` | string | The work currently being pursued |
| `next_action` | string | One executable action for the next agent |
| `tasks` | array | Unique IDs; statuses are `todo`, `doing`, `done`, or `blocked` |
| `decisions` | array | Timestamp, decision, and rationale |
| `verifications` | array | Timestamp, exact command, and observed outcome |
| `changed_files` | array | De-duplicated project-relative POSIX paths |
| `blockers` | array | Real active blocker descriptions; no placeholder values |
| `session.last_summary` | string | Concise recovery summary |
| `session.needs_checkpoint` | boolean | Set by code-file capture; cleared by checkpoint |

At most one task may be `doing`. A project marked `complete` still requires a non-empty `next_action`, such as “No further action; objective verified,” so resuming agents do not infer work from an empty field.

A project with status `blocked` requires at least one blocker. A project with status `complete` cannot retain active blockers. Use checkpoint `--clear-blockers` when previously recorded blockers are resolved.

## Pair arguments

Checkpoint pairs use `left::right`:

```bash
--verification "python3 -m unittest::pass (18 tests)"
--decision "Use atomic JSON writes::Prevents partial state after interruption"
```

The split occurs at the final `::`, allowing earlier colons in commands and prose.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Operation completed |
| `2` | User-correctable board, schema, path, or argument error |

On corrupt JSON or an unsupported schema version, the CLI preserves the source file and exits with code 2.
